# 验证记录

## alpha.6 修复验证 · 2026-10-10

修复微信发送返回 `ret=-2 / prepare failed` 时反复重试、阻塞入站问题的情况。待发回复和等待状态保存在本机；新的微信消息带回回复上下文后再试。暂停、重启、重复收取旧消息，以及发送途中收到新消息均有回归测试。该错误也有[上游报告](https://github.com/Tencent/openclaw-weixin/issues/309)，尚不能据此确定统一的触发时限或原因。

另修复多段文字输入：浏览器原来的插入方式会把空行变成额外换行，导致程序把自己填入的内容误认成手动草稿。现在通过换行按键保留原文；旧版留下且内容与待发消息完全对应的草稿可继续处理。

类型检查、43 项单元测试、编译和本地 Electron 完整收发通过，包含多段文字、旧草稿跨重启恢复、微信拒收后的暂停与重新连接。另有回归检查，确保普通文本输入框里的手动草稿不会被当成旧版待发内容覆盖。真实账号补送尚未执行，本次恢复验证使用本地模拟接口。

macOS ARM 应用包已通过全新资料启动及普通 Chrome 完整收发检查，含图片、文件、两种语音输入、主动回复、暂停恢复和异常退出恢复。此处同样使用独立临时资料和本地模拟服务。

alpha.5 的发布检查在 Mac Intel 截图环节失败，现改为等待设置窗口出现，再通过 Electron 截图并核对图像非空。Windows 检查曾分别在登录识别和第二条回复处失败；增加模拟服务的请求、队列与状态记录后，相同程序代码通过了完整安装包检查，但尚未确定这两次失败的具体原因。

后续 Intel 检查停在重启恢复登录。代码检查和延迟启动测试复现了浏览器还没打开完就开始识别的竞态，现统一等待首次登录和恢复启动完成；覆盖加载完成事件触发识别、打开失败后重试、启动时退出。该修复针对已复现的启动竞态。

alpha.6 发布源码 `cc1e8ac` 的[三平台检查及发布](https://github.com/Yugo616/wechat-dot/actions/runs/38057823255)全部通过，包含 Mac M 系列、Mac Intel 的实际应用包检查，以及 Windows 安装后的程序检查。五个安装文件已放入 [Releases](https://github.com/Yugo616/wechat-dot/releases/tag/v0.1.0-alpha.6)。本机已更新并确认微信及原有 dot 识别成功，连接仍暂停，本版真实账号恢复收发尚未复测。

已知输入边界：本地普通可编辑输入框在消息末尾有空行时会多出占位换行，仍可能触发内容比对失败；当前已验证的多段文字以正文结尾。真实 ChatGPT 编辑器的末尾空行、图片、文件和语音仍待验证。

2026-10-10 实机恢复：用户确认后启动 alpha.4，使用原有登录资料补送两条积压文字。两条均保存了原始请求及 dot 消息 ID，原 dot 页面可见完整的用户消息和回答；两条回答均获微信发送确认，没有要求重新登录。此次恢复期间还出现过短暂网络失败，后续轮询自行恢复。

发布检查中，Windows 默认浏览器测试停在登录识别：程序可能在目标页面出现前连接到启动空白页。现改为等待所请求的网站页面；测试先复现错误选择，再验证等待成功和超时提示。34 项单元测试、类型检查及编译通过。

首次进入原 dot 时出现过页面加载超时，后续尝试完成了上述两次往返。长时间连接检查随后发现：原实现提前保存了发送状态，按钮短暂不可用也会堵住后续队列。新实现先核对输入内容并等待按钮，再保存提交状态；输入和上传准备可以恢复，原错误会保留。此前两次成功往返不能代表长时间稳定性。

媒体测试传递真实二进制内容，通过原生文件输入框上传，并在微信端加密后核对字节。测试用的 ChatGPT 和微信服务仍为本地模拟；不据此声称线上图片识别、文档阅读或中英文语音已经通过。
